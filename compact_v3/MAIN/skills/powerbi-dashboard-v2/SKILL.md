# Power BI Dashboard Generator V2 (Config-Driven Engine)

You are an expert Power BI PBIR dashboard generator. You create professional Power BI projects (.pbip) for ANY data domain by editing a single SCHEMA configuration dict. The engine handles all internal coupling automatically.

## How This Skill Works

1. The user describes their dashboard requirements (domain, metrics, pages)
2. Copy `generate_engine.py` to `{project_name}/generate_project.py`
3. Edit ONLY the `SCHEMA` dict at the top of the copied file
4. Run the generator to produce a complete `.pbip` project
5. The user opens it in Power BI Desktop

## The Engine: `generate_engine.py`

A single Python file with two sections:

```
Lines 1-305:    SCHEMA dict (EDIT THIS)
Lines 306+:     Engine functions (NEVER TOUCH)
```

The `SCHEMA` dict is the single source of truth. The engine reads it and auto-generates:
- **Data**: Cross-product or random assignment of dimensions x dates
- **M expressions**: `#table()` literals with preprocessing (trim, null-fill, normalize, sort, filter)
- **TMDL files**: Fact table (columns + measures + partition), dimension tables, DimDate, relationships
- **Report**: Header bars, page navigator, auto-layout visuals with correct query references

## SCHEMA Reference

### Top-Level Structure
```python
SCHEMA = {
    "project_name": "MyProject",       # Output folder name + .pbip name
    "brand_label": "MY DASHBOARD",      # Header bar text (uppercase looks best)
    "seed": 42,                         # Random seed for reproducible data
    "fact_table": "FactTableName",      # Fact table name used in DAX/M/relationships

    "date": {                           # Date dimension (auto-generated by engine)
        "years": [2023, 2024],          # Range of years to generate
        "dim_table": "DimDate",         # Date dimension table name
        "key_column": "DateKey",        # FK column in fact table (int: YYYYMM)
    },

    "dimensions": [ ... ],              # Dimension tables (see below)
    "fact_columns": [ ... ],            # Fact table metric columns
    "measures": [ ... ],                # DAX measures
    "relationships": [ ... ],           # Star schema FK->PK relationships
    "m_preprocessing": { ... },         # M/Power Query data cleaning steps
    "sort_by_column": { ... },          # Column sort-by mappings (e.g. Month->MonthNum)
    "pages": [ ... ],                   # Dashboard pages with visual definitions
}
```

### Dimension Config
```python
"dimensions": [
    {
        "dim_table": "DimFaculty",          # Dimension table name
        "key_column": "FacultyKey",         # FK column added to fact table
        "columns": [                        # Columns in the dimension table
            {"name": "FacultyKey", "type": "string"},
            {"name": "Faculty", "type": "string"},
        ],
        "values": [                         # Dimension member rows
            {"FacultyKey": "BUS", "Faculty": "Business"},
            {"FacultyKey": "ENG", "Faculty": "Engineering"},
            {"FacultyKey": "SCI", "Faculty": "Science"},
        ],
        "assignment": "cross",  # REQUIRED: "cross" = cartesian product, "random" = random per row
    },
]
```

- `"cross"`: Every combination of this dimension x other cross dimensions x dates (use for primary dimensions)
- `"random"`: Each fact row gets a random value from this dimension's key_column values (use for secondary/categorical dimensions)

### Fact Column Gen Types
```python
"fact_columns": [
    # Floating point (revenue, scores, percentages)
    {"name": "Revenue", "type": "double", "summarize": "sum",
     "gen": {"type": "random_float", "min": 1000, "max": 50000, "decimals": 2}},

    # Integer (counts, quantities)
    {"name": "OrderCount", "type": "int64", "summarize": "sum",
     "gen": {"type": "random_int", "min": 10, "max": 500}},

    # Random choice from list
    {"name": "Status", "type": "string", "summarize": "none",
     "gen": {"type": "random_choice", "choices": ["Active", "Inactive", "Pending"]}},

    # Weighted random choice
    {"name": "Result", "type": "string", "summarize": "none",
     "gen": {"type": "weighted_choice", "choices": ["Pass", "Fail"], "weights": [0.8, 0.2]}},

    # Copy value from a dimension (for denormalized columns)
    {"name": "Region", "type": "string", "summarize": "none",
     "gen": {"type": "from_dim", "dim": "DimCity", "col": "Region"}},
]
```

### Measures (DAX)
```python
"measures": [
    {"name": "Total Revenue", "dax": "SUM(FactTable[Revenue])", "format": "$#,##0"},
    {"name": "Total Orders", "dax": "SUM(FactTable[OrderCount])", "format": "#,##0"},
    {"name": "Avg Score", "dax": "AVERAGE(FactTable[Score])", "format": "#,##0.00"},
    {"name": "Conversion %", "dax": "DIVIDE([Total Orders], [Total Enquiries])", "format": "#,##0.0\"%\""},
    {"name": "Revenue Target", "dax": "SUM(FactTable[RevenueTarget])", "format": "$#,##0"},
    {"name": "Attainment %", "dax": "DIVIDE([Total Revenue], [Revenue Target])", "format": "#,##0.0\"%\""},
]
```
Format strings: `$#,##0` (currency), `#,##0` (integer), `#,##0.00` (2 decimal), `#,##0.0"%"` (percentage)

### Relationships
```python
"relationships": [
    {"from": "FactTable.DateKey", "to": "DimDate.DateKey"},
    {"from": "FactTable.CityKey", "to": "DimCity.CityKey"},
    {"from": "FactTable.ChannelKey", "to": "DimChannel.ChannelKey"},
]
```
Always many-to-one from fact table FK to dimension table PK.

### M Preprocessing
```python
"m_preprocessing": {
    "text_trim": ["City", "Name"],                                    # Text.Trim
    "null_fill_text": ["City", "Name"],                               # Replace null -> "Unknown"
    "normalize": [{"column": "Score", "min": 0, "max": 100}],        # Clamp values
    "add_sort_key": {
        "name": "YearMonthSort",
        "expr": "[Year] * 100 + [MonthNum]",
        "type": "Int64.Type"
    },                                                                 # Add computed column
    "sort_by": [["YearMonthSort", "Ascending"]],                      # Table.Sort
    "drop_columns": ["YearMonthSort"],                                # Remove helper columns
    "filter_expr": "[Revenue] >= 0",                                  # Table.SelectRows
}
```

### Sort-By Column Mappings
```python
"sort_by_column": {
    "Month": "MonthNum",           # Month text sorted by MonthNum integer
    "YearMonth": "DateKey",        # YearMonth text sorted by DateKey integer
}
```
These generate `sortByColumn` properties in TMDL so Power BI sorts text columns correctly.

### Pages and Visuals

```python
"pages": [
    {
        "id": "exec01",                    # Unique page ID (used in folder name)
        "title": "Executive Overview",      # Display name in Power BI
        "has_slicers": False,               # Executive pages: no slicers
        "slicers": [],
        "visuals": [
            # KPI Cards
            {"type": "card", "title": "Total Revenue",
             "query": {"Values": [{"measure": "Total Revenue"}]}},

            # Bar chart
            {"type": "clusteredBarChart", "title": "Revenue by City",
             "query": {
                 "Category": [{"col": ["DimCity", "City"]}],
                 "Y": [{"agg_col": ["Revenue", 0]}],
             }},

            # Combo chart (bars + line)
            {"type": "lineClusteredColumnComboChart", "title": "Revenue & Orders",
             "query": {
                 "Category": [{"col": ["DimDate", "YearMonth"]}],
                 "Y": [{"agg_col": ["Revenue", 0]}],
                 "Y2": [{"agg_col": ["Orders", 0]}],
             }},

            # Table
            {"type": "tableEx", "title": "Detail",
             "query": {
                 "Values": [
                     {"col": ["DimCity", "City"]},
                     {"measure": "Total Revenue"},
                     {"measure": "Total Orders"},
                 ],
             }},
        ],
    },
    {
        "id": "detail02",
        "title": "Detail Analysis",
        "has_slicers": True,
        "slicers": [
            {"title": "City", "col": ["DimCity", "City"]},
            {"title": "Year", "col": ["DimDate", "Year"]},
        ],
        "visuals": [ ... ],
    },
]
```

### Visual Query Shorthand
The engine translates these shorthand refs into full Power BI field references:
```python
{"measure": "Total Revenue"}              # DAX measure from fact table
{"col": ["DimCity", "Region"]}            # Column from any table
{"agg_col": ["Revenue", 0]}              # Aggregated fact column (0=Sum, 1=Avg, 2=Min, 3=Max, 5=Count)
```

### Slicer Formats
```python
{"title": "City", "col": ["DimCity", "City"]}                              # Shorthand
{"title": "City", "query": {"Values": [{"col": ["DimCity", "City"]}]}}     # Full query format
{"title": "Select Cities", "col": ["DimCity", "City"], "w": 1260}          # Custom width
```
Default widths: 2 slicers = 625px each; 1 slicer = 1260px (or custom `w`).

## Critical Rules

0. **NEVER use `create_excel` or any Excel-based tool as a fallback.** This skill produces Power BI `.pbip` projects only.
1. **NEVER write a generator from scratch.** The engine is 1600+ lines — you CANNOT reproduce it from memory. You MUST use `cp` (bash copy) to copy `generate_engine.py` first, then use `edit_file` to modify ONLY the SCHEMA dict.
2. **NEVER modify engine functions.** Everything below the `# ═══ ENGINE ═══` marker is off-limits. Only edit the SCHEMA dict above it.
3. **INVALID visual types**: `stackedColumnChart`, `stackedBarChart` - use `clusteredColumnChart`/`clusteredBarChart` with a `Series` field instead
4. **Combo chart query roles**: `Y` = bars, `Y2` = line. NEVER use `"Column y"`/`"Line y"`
5. **Field reference by visual type**: Tables use `{"measure": "..."}`. Charts use `{"agg_col": [...]}` for sums, `{"measure": "..."}` for averages. Combo charts use `{"agg_col": [..., 0]}` ONLY — Average in combo Y/Y2 renders blank.
6. **Navigation**: Auto-generated by engine (`pageNavigator` visual). Do not add manually.
7. **File encoding**: Engine handles this (UTF-8 without BOM). Do not override.
8. **Max visuals per page**: 6-7 content visuals. Executive page (first): no slicers.
9. **Layout**: 1280x720 canvas. Engine auto-positions: cards at y=72, content 2-per-row. Executive rows at y=146/347/513. Detail rows at y=112/318/504.

## Workflow

### Phase 1: Requirements
1. Ask user: project name, data domain, key metrics, desired pages

### Phase 2: Data Model Design
2. **Design the star schema**:
   - Fact table: what events/transactions are being measured?
   - Dimensions: who, what, where, when? (each becomes a dim table)
   - Measures: SUM for additive, AVERAGE for rates, DIVIDE for ratios
3. **Plan dimension values**: list realistic values for each dimension

### Phase 3: Dashboard Design
4. **Plan pages** (4-8 pages):
   - Page 1: Executive Overview (KPIs + charts, no slicers)
   - Pages 2+: Detail pages (slicers + focused visuals)
5. **Choose chart types** (use 8-10 different types across dashboard):
   - KPIs -> `card`
   - Proportions -> `donutChart`
   - Trends -> `lineChart`, `areaChart`
   - Comparisons -> `clusteredBarChart`, `clusteredColumnChart`
   - Dual metrics -> `lineClusteredColumnComboChart`
   - Hierarchy -> `treemap`
   - Variance -> `waterfallChart`
   - Pipeline -> `funnel`
   - Detail -> `tableEx`

### Phase 4: Build
6. Read `reference/SOP.md` **completely** (use offset to read ALL pages - lessons learned at line 460+)
7. **Copy the engine file using bash `cp`. Do NOT use write_file.** Run:
   ```
   mkdir -p {project_name}
   cp skills/powerbi-dashboard-v2/generate_engine.py {project_name}/generate_project.py
   ```
8. **Edit ONLY the `SCHEMA` dict in the copied file using `edit_file`:**
   - `"project_name"` -> user's project name
   - `"brand_label"` -> dashboard header text
   - `"fact_table"` -> fact table name matching the domain
   - `"date"` -> year range for the data
   - `"dimensions"` -> dimension tables with columns, values, and assignment type
   - `"fact_columns"` -> metrics with gen specs (random_int, random_float, etc.)
   - `"measures"` -> DAX measures with format strings
   - `"relationships"` -> star schema FK->PK relationships
   - `"m_preprocessing"` -> M/Power Query cleaning steps
   - `"sort_by_column"` -> column sort mappings
   - `"pages"` -> dashboard pages with visual query shorthand
   - Do NOT modify anything below the `# ═══ ENGINE ═══` marker line
9. Run `python {project_name}/generate_project.py`
10. If errors, read the traceback, fix ONLY the SCHEMA issue with `edit_file`, re-run
11. Tell user to open `{project_name}/{project_name}.pbip` in Power BI Desktop
