4. Compaction - 4-Tier System

Cheapest first: Cached MC (free) -> Time-Based MC (no LLM) -> Snip (no LLM) -> Full AutoCompact (LLM call). Each tier only fires if cheaper tiers insufficient.

7. Security Architecture

Read-only tools auto-approved. Bash goes through classifier + speculative pre-check. Trust boundary enforced in system prompt.

Runnable Features NOT in V4

Gaps ordered by priority. Some are inherent to the SageMaker environment (marked N/A).

FeatureRunnable ImplementationWhy Missing / Priority
Parallel Safe Tool Execution partitionToolCalls() groups consecutive read-only tools. Up to 10 run in parallel. StreamingToolExecutor.addTool() starts execution AS blocks stream in. V4.2.1 Closed. V4 now batches consecutive read-only tools and runs them concurrently via ThreadPoolExecutor. Remaining gap is only true streaming execution while the model is still emitting tool blocks.
Cached Microcompact (cache_edits) Sends cache_edits API block to delete tool results from server cache WITHOUT modifying local messages. Zero cache invalidation. HIGH Requires Anthropic cache_edits API support via Bedrock. Not available on Bedrock yet. Would save significant cost at high context.
Snip Compaction snipProjection.ts + HISTORY_SNIP feature flag. Remove oldest conversation boundary without LLM call. MEDIUM V4 goes straight from micro to full compact. Snip would be a middle-ground option. Feature-flagged even in runnable.
FILE_UNCHANGED_STUB If file not changed since last read, return short stub instead of full content. Saves context. V4.2.1 Closed. V4 now returns an unchanged-file stub before the generic in-context hint, so repeated unchanged reads stay cheap.
PTL (Prompt-Too-Long) Recovery truncateHeadForPTLRetry() - if compact itself hits prompt-too-long, iteratively drops oldest rounds. Up to 3 retries. V4.2.1 Closed at practical parity. V4 now trims the oldest summary context and retries compaction up to 3 times when Bedrock returns prompt-too-long.
Streaming Tool Execution StreamingToolExecutor starts tool execution AS tool_use blocks stream in (before full response received). LOW SageMaker/Bedrock latency characteristics differ. V4 waits for full response then dispatches. Streaming within Jupyter is complex.
ML Bash Classifier ML model predicts bash command danger level. Speculative pre-check runs during previous tool execution. LOW V4 uses regex denylist + RO classifier. Adequate for SageMaker single-user. ML classifier too complex to ship.
Cache Break Detection Hashes system prompt + tool schemas. Post-call: detects if cache_read_input_tokens dropped >5%. Logs reason. LOW Useful for cost monitoring but not functional. V4 doesn't expose cache analytics.
Immutable Message Design Messages never mutated after creation. Enables byte-level prompt cache matching across turns. MEDIUM V4 mutates messages (content-clear in microcompact). Causes cache misses on cleared sections. Could redesign but complex.
7 Message Types AssistantMessage, UserMessage, SystemMessage, ProgressMessage, AttachmentMessage, ToolUseSummaryMessage, TombstoneMessage LOW V4 uses plain dicts. Adequate for Bedrock Converse API. TombstoneMessage (graceful degradation) is interesting but not critical.
Worktree Isolation Sub-agents run in git worktree - isolated repo copy, no interference, auto-cleanup. LOW V4 sub-agents share workspace. Not critical for SageMaker single-user.
Per-File Memory Storage Individual .md files per memory item. MEMORY.md is just an index. LOW V4 uses single flat file. Fine for SageMaker where memory stays small.
Memory Extraction as Fork Extraction runs as a forked sub-agent with full conversation context + parallel read strategy. LOW V4 does single LLM call. Simpler, adequate for session sizes.
Feature Flags PRIMETIME, CONSULTANT_MODE, TOOL_SNAPSHOT, HIDDEN, TEAMWORK - runtime feature toggles. N/A V4 uses config file. Feature flags are for multi-user SaaS deployment.
Auto-Dream (Cross-Session Consolidation) After 24h+5 sessions, auto-consolidates memories across sessions. N/A SageMaker sessions are independent. Cross-session consolidation requires persistent state.
Retry Logic (529 + PTL) 10 retries, 500ms base delay, 3 max 529 retries. Unattended mode: infinite retries with 5min backoff. MEDIUM V4 has basic retry but not as sophisticated. Could add exponential backoff.
Model Hierarchy (Haiku/Capybara/Opus) Different models for different tasks: Haiku for classification, Capybara for inner calls, Opus for main. MEDIUM V4 supports model override per agent type via CONFIG.agent_overrides. Not fully utilized yet.
Sub-Agent State Isolation Module-level state (context collapse, memory cache) reset per sub-agent scope. MEDIUM V4 sub-agents share _FILE_READ_TIMES, _FILES_READ globals. Could corrupt on concurrent sub-agents.

Features Where V4 Exceeds the Runnable

V4 isn't just a copy - it has features the runnable doesn't have, specifically optimized for SageMaker/Bedrock.

FeatureV4Runnable
CATASTROPHIC_PATTERNS LAYER -1 Precompiled hard-block patterns. Cannot be disabled by ANY config, user approval, or allowlist modification. Fail-closed: bad regex fails at import. YOLO classifier is configurable and can be overridden.
Doom Loop Detection Hash-based 3-repeat threshold with deque(30) history. Per-tool target extraction (filepath@offset, pattern, MD5). Catches infinite tool loops before context exhaustion. No equivalent. Relies on turn budget to catch loops indirectly.
Audit Trail with Integrity Local JSONL with SHA-256 hashes. Enterprise-appropriate for regulated environments. Telemetry-based. Sends data to Anthropic servers.
Tool Auto-Repair (5 layers) Case-insensitive lookup, fuzzy prefix match, argument auto-fix (path -> file_path, text -> content), type coercion. Reduces wasted turns. Basic error messages. No auto-repair.
Session Budget Enforcement session_cost_limit with 80%/100% thresholds. Warns then stops. Tracks across all calls in session. maxBudgetUsd per-turn only. No persistent session guard.
Docker Execution Sandbox Optional rootfs/network isolation for bash and python_exec. Executes in-process. Relies on permission system only.
Bedrock-Specific Robustness Role alternation enforcement, cache fallback on unsupported models, AU regional pricing (10% premium), 600s read timeout. Targets Anthropic API directly. No Bedrock-specific handling.
Pre-Edit Staleness Check Tracks file mtime. Aborts edit_file if externally modified since last read (0.5s tolerance). No equivalent. Trusts LLM to re-read if needed.
Post-Edit Git Diff After every edit_file, appends git diff HEAD (3000 char cap, 5s timeout) to tool result. No equivalent. User must manually check diffs.
Lazy Doc Tool Loading Scans last 4 messages for document keywords. Excludes 6 doc tools if not needed (~1-2K token savings per call). All tools sent every call. No lazy loading.
Python AST Security (3-layer) Regex + AST import validation + AST call validation catches aliased dangerous calls. No python_exec equivalent. Bash-only execution.
Compact Circuit Breaker After 3 consecutive compact failures, auto-compact paused. Manual button still works. Pre-send also tracked. No circuit breaker. Failed compacts retry indefinitely.

Post-Compact Cleanup (Runnable)

Clears: microcompact state, context collapse store (main thread only), getUserContext memoize cache, CLAUDE.md/memory file cache, system prompt sections, classifier approvals, speculative checks, beta tracing state, session messages cache.

Does NOT clear: invoked skill names (skills survive compaction - avoids 4K token cache_creation on re-inject).

Retry Logic (Runnable)

DEFAULT_MAX_RETRIES = 10, BASE_DELAY_MS = 500
Only foreground sources retry on 529 (capacity). Background sources (titles, summaries) bail immediately.
MAX_529_RETRIES = 3
Unattended mode: indefinite retries with up to 5min backoff + 30s heartbeat yields.

Task Types (Runnable)

7 types: local_bash, local_agent, remote_agent, in_process_teammate, local_workflow, monitor_mcp, dream.
Each has a typed prefix for IDs (b/a/r/t/w/m/d). Task IDs = 36^8 random bytes.

Auto-Dream (Cross-Session Memory)

Gate: (1) time > 24h since last consolidation, (2) >= 5 sessions with mtime > lastConsolidatedAt.
Runs /dream prompt as forked sub-agent with createCacheSafeParams.
Session scan interval: 10 minutes. Disk lock prevents concurrent consolidation.

Token Estimation Breakdown (Runnable)

estimateMessageTokens() counts by block type:
- text -> roughTokenCountEstimation(text)
- thinking -> roughTokenCountEstimation(thinking)
- tool_result -> sum of content items
- image/document -> 2000 tokens flat
- tool_use -> name + JSON(input)
- Final: Math.ceil(totalTokens * (4/3))
