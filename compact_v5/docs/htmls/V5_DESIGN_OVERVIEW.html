A simple final map of v5: what it is, how it works, what we learned from Runnable, v4, Hermes, and Learning Factory, what was implemented, what was not copied, and how the AWS tests proved readiness.

Explain It Like You Are 9

v5 is a robot programmer for SageMaker. It has a brain, a notebook, a toolbox, helper workers, a money meter, and inspectors.

Extended thinking is handled like a signed permission slip. Bedrock may return a thinking block with a signature. On the next turn, v5 may include the previous assistant message again as conversation history, but it must replay only the original signed thinking block. v5 never invents an unsigned thinking block from display text. The UI shows a readable copy for the operator, while the runtime keeps Bedrock's signed block separate.
Final state: Claude approved v5.0.1 production readiness after the AWS/R-tier loop. The matrix ended with 28 `READY` rows and 14 `DISPOSITION_OK` rows. Local Bedrock spend recorded by the test ledger was `$1.6757 / $14.25`.
Current 2026-05-12 readiness update: v5 is 98% production-test ready for the target SageMaker validation round. It keeps the latest v4.10.10 notebook user contract, restores v4-style ipywidgets as the normal path, absorbs relevant Runnable agentic patterns, passes 31 focused smoke tests, has local Jupyter/Playwright visual evidence, and ships in a rebuilt verified zip. The remaining risk is target-environment variance: SageMaker widget manager, IAM credentials, and installed packages.

Architecture Flow

No Mermaid is used here, so the diagram cannot fail from Mermaid syntax. Read left to right.

Main Agent Loop

1. User taskNotebook, chat, or command asks for software work.
2. Load statePrompt, memory, status, todos, skills, and saved session state.
3. Model turnBedrock Claude decides whether to answer or use tools.
4. Tool workRead, edit, shell, notebook, todo, task, result replay, or checkpoint.
5. EvidenceLogs, telemetry, costs, status, and tests are saved.
If the task is not done, v5 loops. If context is large, v5 compacts and resumes from saved state.

Long Software Task Loop

PlanBreak task into clear work items.
BuildMake a focused code change.
TestRun local or AWS tests only when allowed.
ReviewSelf-review and Claude review check evidence.
CheckpointCommit and push specific files.

Subagent And Reviewer Loop

ParentOwns the full user goal.
SubagentGets a bounded helper task and budget.
EnvelopeReturns files, findings, costs, errors, and next steps.
Claude reviewerReads repo files itself, row by row.
Close gateBlocks done if evidence is missing.

What We Learned From Other Systems

ReferenceLesson Used In v5What We Did Not Copy
Runnable Claude CodeContext compaction, cache thinking, skill discovery, model switch, tool-loop controls, subagent/reviewer discipline, and long-task status handling.We did not copy the exact UI, streaming assumptions, or every Claude Code internal behavior because v5 runs in SageMaker/Bedrock.
v4SageMaker notebook shape, dark chat UI, model picker, session controls, Compact/Clean, practical local tools, Bedrock constraints, and earlier working UX were kept as anchors.We did not keep v4's weaker long-run memory/status discipline or monolithic internals. v5 adds stronger gates, telemetry, modular code, and subagent envelopes.
Hermes agentNon-streaming concurrency ideas, robust tool orchestration, and production-agent failure handling informed the no-streaming adaptation.We did not adopt incompatible streaming-first assumptions.
Learning FactoryNo-drift process: save prompts, reviews, ledgers, status, lessons, and proof before claiming done.We did not make the human sit at every step. v5 uses persisted gates and checkpoint evidence so it can run longer safely.

No-Drift Review System

This is the big lesson from the completion incident: a worker can sound confident while scope is missing. v5.0.1 fixed the process by making evidence row-by-row.

GateWhat It Prevents
Scope auditStops silent narrowing of planned scope.
Worker self-reviewStops the worker from claiming done without checking itself.
Claude independent reviewStops trusting the worker prompt alone. Claude must read files from disk.
R-tier gateStops AWS test rows from being marked ready without required evidence.
Git checkpointStops untraceable progress and gives rollback points.

What The Tests Proved

Test GroupWhat It Proved
R1-R5Basic coding, compaction recall, subagents, cold-cache microcompact, and exec recovery.
R6-R12Dream memory, model switch, mock edge handling, approvals/dispositions, save/restart/load, and Sonnet end-to-end artifacts.
R13-R17Real software-building ability: coding accuracy, refactor, debugging, long app build, and thinking visibility.
R18 edge cases429/5xx handling, corrupt session files, large output replay, disk-full safety, audit retention, Unicode memory, and command safety.
R19 UX/recoveryAmbiguity, contradictions, hidden dependencies, subagent conflict/failure, repeated-call circuit breaker, memory conflict, and long coherence.
Important: some tests intentionally use mock or reviewed disposition evidence because they are safer and more precise than wasting AWS calls. The final gate accepts those only when the matrix says that evidence type is allowed.
