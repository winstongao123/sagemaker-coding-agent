Simple Version

Think of v5 like a careful robot programmer with a notebook, a toolbox, helper workers, and a safety inspector.

NotebookIt saves status, memory, todos, checkpoints, and logs so it can continue after a long task or compaction.
ToolboxIt can read files, edit files, run commands, inspect results, and test software.
HelpersIt can call subagents for smaller jobs, then collect their results in a structured envelope.
InspectorIt uses review gates, Claude review, local tests, and AWS tests before saying "ready."
Money MeterIt records tokens, cache use, tool calls, model calls, and cost so AWS spend does not become a surprise.
Stop SignIf evidence is missing, tests fail, review fails, or cost is unsafe, it must stop or fix before moving on.

Main Loop

Every user message goes through the same control loop. The loop is designed to keep long software tasks from drifting.

1. Load ContextRead prompt rules, memory, status, todos, skills, and saved state.
2. Plan WorkUnderstand the task and choose tools or subagents.
3. Call ModelAsk Bedrock Claude for the next action, with context and tool schemas.
4. Run ToolsRead, edit, run tests, inspect files, or dispatch subagents.
5. Save EvidenceWrite status, logs, tool results, telemetry, and checkpoints.
6. VerifyRun tests, review, cost gates, and close only when evidence is clean.

Review And No-Drift System

What "Done" Means

A block is not done just because the worker says it is. It needs row-by-row scope evidence, local tests, logs, review artifacts, a clean scope audit, and a pushed checkpoint.

How Claude Review Works

Codex gives Claude instructions and file locations. Claude should read the real files itself, reconstruct the scope, review each row, and write a verdict. Codex should not paste full repo files as the evidence source.

GateQuestion It Answers
Scope auditDid every planned row get shipped, deferred by user, dropped by user, or marked N/A with evidence?
Worker self-reviewDid the worker check its own claim before asking for close?
Claude row reviewDid an independent reviewer inspect the actual files and evidence?
Git checkpointCan we track, compare, and roll back every closed block?
Final readiness reviewAre all local gates, AWS evidence, metrics, and follow-up dispositions clean enough to approve production readiness?
