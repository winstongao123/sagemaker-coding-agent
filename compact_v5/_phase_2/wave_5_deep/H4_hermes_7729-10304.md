## 3. New findings beyond Block N

The following are present in this chunk and **NOT yet captured** in Q1 evidence matrix or Block N. Each is independently useful and decision-required for v5.

### F1. `_sanitize_tool_call_arguments` (lines 7791-7898) — corrupted-args repair
Walks the messages list, finds assistant `tool_calls`, validates each `arguments` field is parseable JSON, and on `JSONDecodeError`:
- Replaces `arguments` with `"{}"` in-place.
- Inserts a synthetic `role: tool` message containing `_TOOL_CALL_ARGUMENTS_CORRUPTION_MARKER` so the model sees what failed.
- Idempotent — prepends marker to existing tool message if one is already present.

**v5 relevance**: Bedrock Claude does occasionally emit malformed JSON (especially long heredocs in `terminal` calls). This is a **defensive layer** that prevents 400-class errors mid-loop. Not in Q1, not in Block N, not in Block L. **Recommend new PORT_LOG row** (Block L extension or new Block N row 6).

### F2. `flush_memories` (lines 7913-8157) — pre-compression memory flush
Before every `_compress_context` call (and at session end), the agent gets ONE turn with only the `memory` tool exposed, an aux-client API call (cheaper non-Codex path), and any returned memory tool calls are executed before context drops. Sentinel-based cleanup (`_flush_sentinel`) ensures flush artifacts never leak into stored history.

**v5 relevance**: v5's compactor is "Block A combined v4 + Runnable". Q1 says BLOCK A is "COMBINED v4 + Runnable" — does it include this PRE-compression flush? v4's `compact_v4/MAIN/agent/sagemaker_agent.py` does NOT (verified — only 3 ThreadPoolExecutor sites at v4:9271/9310/9328 are for approval batching, no `flush_memories` equivalent). **GAP-4**: confirm Block A includes pre-compression memory flush; if not, this is a Hermes net-new for v5 memory durability.

### F3. `_compress_context` post-compression hardening (lines 8158-8272)
Several tightenings beyond a vanilla "summarize then continue":
- (8202-8204) Re-injects `todo_snapshot` into compressed messages so the todo list survives.
- (8210-8238) **Splits the SQLite session** with `parent_session_id` linking, propagates and auto-numbers session title (e.g. "session" → "session 2"), resets `_last_flushed_db_idx`. Hermes treats compaction as a session boundary.
- (8261-8265) `reset_file_dedup(task_id)` — clears the file-read dedup cache so the model can re-read files whose summary in compaction was lossy.
- (8242-8247) Warns user after ≥2 compressions ("accuracy may degrade — consider /new").
- (8255-8256) Updates `last_prompt_tokens` so post-compaction pressure calc isn't stale.

**v5 relevance**: v4's compactor is a single-pass summarizer; none of these five details exist in v4. **GAP-5**: Q1 BLOCK A says "COMBINED v4 + Runnable" but doesn't mention these Hermes-specific tightenings. Recommend either: (a) adopt items 1, 3, 5 in Block A (todo re-inject, file-dedup reset, token-pressure refresh), and skip items 2, 4 (session-split = SQLite-specific to Hermes; warning = quality-of-life). (b) document explicitly that these Hermes details were considered and which were dropped.

### F4. `_execute_tool_calls`'s `_executing_tools = True` flag (lines 8284, 8295)
Flips a boolean during tool execution so `_vprint` is allowed even while a stream consumer is active (otherwise stream consumers would suppress the per-tool messages). Tiny detail but **changes UX** — without this, parallel tool execution under streaming is silent.

**v5 relevance**: v4 chat.ipynb canonical UI doesn't stream the same way, but if v5 adds streaming (Q1 BLOCK E+F: "Chat UI+Widgets"), this flag is required. Low priority — flag for awareness only.

**v5 relevance**: v5 has no `delegate_task`, but v5 has `tool_create_chart`, `tool_semantic_search`, etc. (Block T). The pattern is generalizable. NOT a port — a design rule. Worth one line in v5 STATE.md.

Hard-coded ceiling. v5 single-user SageMaker likely runs on a single kernel — 8 may be excessive (could exhaust file descriptors when reading 8 files simultaneously inside Bedrock LCC). **Recommend v5 set to 4** unless benchmarked otherwise.

### F7. `run_conversation` preamble (9280-9499) — turn-start contract
Captures a number of per-turn invariants:
- (9310) `_install_safe_stdio()` — guards against `OSError` from broken pipes (systemd/headless/daemon).
- (9320) `_restore_primary_runtime()` — undoes prior-turn fallback so this turn retries primary first.

Recommend port.
- (9354-9364) Reset 8 retry counters per turn (`_invalid_tool_retries`, `_invalid_json_retries`, `_empty_content_retries`, `_incomplete_scratchpad_retries`, `_codex_incomplete_retries`, `_thinking_prefill_retries`, `_post_tool_empty_retried`, `_unicode_sanitization_passes`). v5: 4-5 of these are Codex/Anthropic-specific and don't apply to Bedrock; ≥3 should remain (`_invalid_tool_retries`, `_empty_content_retries`, `_unicode_sanitization_passes`).

### F8. Preflight context compression (9502-9561)
Computes `estimate_request_tokens_rough(messages, system_prompt, tools=self.tools)` BEFORE the loop and runs up to 3 compression passes if over threshold. Triggered when user **switches to a smaller-context model mid-session**. Includes:
- Tool-schema tokens in estimate (comment 9507 explicitly: "with many tools these can add 20-30K+ tokens that the old sys+msg estimate missed entirely").
- Resets `_empty_content_retries`, `_thinking_prefill_retries`, `_last_content_with_tools` after compression — so the next attempt gets a fresh budget on compressed context. **Critical** — comment at 9544 says without this "the model hits '(empty)' immediately after compression-induced context loss".

**v5 relevance**: v4 baseline doesn't model-switch mid-session, so multi-pass preflight is over-engineered. But the **tool-schema-tokens-in-estimate** detail and **post-compression retry-counter reset** are universal. **GAP-7**: ensure Block A compactor estimate includes tool tokens; and post-compression counter reset is in v5's retry handler.

### F9. Plugin pre_llm_call context injection (9563-9597)
Plugin hook returning context that is appended to the **current turn's user message** (NOT system prompt — comment 9568 is explicit: "this preserves the prompt cache prefix"). Architectural rule: never append to system prompt at API-call time, always to user message.

**v5 relevance**: v5 has no plugin system. The **architectural rule** (only mutate user message, never cache-prefix) generalizes to any per-turn context injection. Important for Block A + memory-manager work. Recommend codify as a v5 architecture rule.

### F10. Per-turn cleanup of dead TCP connections (9369-9378)
`self._cleanup_dead_connections()` for non-Anthropic providers — cleans up zombie sockets from prior outages. Bedrock's boto3 client manages its own pool; **not portable** to v5.

### F11. `_drain_pending_steer` pre-API-call drain (9722-9758)

**v5 relevance**: v5 ships `chat.ipynb` canonical UI which does NOT have a `/steer` mid-turn capability. Drop. Note for future: thread-safety pattern (lock-protected text buffer) is reusable.
