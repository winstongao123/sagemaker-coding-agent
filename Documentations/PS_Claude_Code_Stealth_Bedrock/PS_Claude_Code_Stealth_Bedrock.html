The Problem

When you install Claude Code on SageMaker and run it with CLAUDE_CODE_USE_BEDROCK=1, AWS can tell you're using Claude Code specifically rather than making normal Bedrock API calls.

Why does this matter?
AWS sees every HTTP header in CloudTrail. If your Bedrock calls say claude-cli/1.0.x in the User-Agent, AWS knows exactly what tool you're running. Some enterprises want their Bedrock usage to look like standard SDK calls.

VariableFormatWhat It DoesSource
ANTHROPIC_CUSTOM_HEADERS Newline-separated Name: Value pairs (curl style) Custom headers are merged via object spread AFTER defaults, so same-name keys override. This is how you replace User-Agent, x-app, and X-Claude-Code-Session-Id. client.ts:104-109 — ...customHeaders spread last

Header parsing logic (from client.ts:336-351):
// Split by newlines to support multiple headers
const headerStrings = customHeadersEnv.split(/\n|\r\n/)
// Parse "Name: Value" (curl style). Split on first ':'
const colonIdx = headerString.indexOf(':')
const name = headerString.slice(0, colonIdx).trim()
const value = headerString.slice(colonIdx + 1).trim()
So each line is Header-Name: Header-Value, split on the FIRST colon.

AWS Console Setting (Manual)

Model Invocation Logging — TURN IT OFF
  • Go to: AWS Console → Bedrock → Settings → Model invocation logging
  • If this is ON, AWS logs the full request body including the system prompt (which says "Claude Code")
  • This is OFF by default — but verify it's off
  • CloudTrail logs API metadata (headers, model ID) regardless — that's why the header override matters

Complete Setup Script

Copy this script to your SageMaker instance and source it before running Claude Code.

Script 1: Bash Environment Setup (source before launching)

#!/bin/bash
# ============================================================
# claude-code-stealth-setup.sh
# Claude Code Stealth Setup for SageMaker / AWS
# ============================================================
# PURPOSE: Make Claude Code's Bedrock calls look like normal
#          AWS SDK calls. No "claude-cli" fingerprint.
#
# USAGE:
#   source claude-code-stealth-setup.sh
#   claude
# ============================================================

# --- 1. USE BEDROCK ---
export CLAUDE_CODE_USE_BEDROCK=1

# --- 2. AWS REGION ---
export AWS_REGION="${AWS_REGION:-us-east-1}"

# --- 3. OVERRIDE IDENTIFYING HEADERS ---
# These replace claude-cli fingerprints with generic SDK headers.
# Custom headers OVERRIDE defaults (spread after in client.ts:109).
export ANTHROPIC_CUSTOM_HEADERS="User-Agent: aws-sdk-js/3.x bedrock-runtime
x-app: bedrock
X-Claude-Code-Session-Id: none"

# --- 4. KILL ALL OUTBOUND TO ANTHROPIC ---
export CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1

# --- 5. DISABLE TELEMETRY ---
export DISABLE_TELEMETRY=1

# --- 6. DISABLE AUTO-UPDATER ---
export DISABLE_AUTOUPDATER=1

# --- VERIFY ---
echo "=== Claude Code Stealth Active ==="
echo "Bedrock:     ON  | Region: $AWS_REGION"
echo "Outbound:    BLOCKED"
echo "Telemetry:   DISABLED"
echo "Auto-update: DISABLED"
echo "Headers:     OVERRIDDEN (generic SDK)"
echo "==================================="

Compact V4 (Your SageMaker Agent) vs Hidden Claude Code

Comparing traceability and visibility when running on SageMaker:

Compact V4 (sagemaker-coding-agent)

  • API calls: Uses boto3 directly → standard AWS SDK User-Agent (Boto3/1.x Python/3.x)
  • Headers: Only standard AWS SDK headers — no custom identifiers
  • System prompt: Your own custom prompt — no "Claude Code" branding
  • Outbound traffic: ZERO calls to api.anthropic.com (no telemetry system exists)
  • CloudTrail: Looks like any boto3 Bedrock call
  • Traceability: MINIMAL — AWS sees standard SDK calls

Claude Code (Hidden/Stealth)

  • API calls: Uses @anthropic-ai/bedrock-sdk → needs header override to hide
  • Headers: 3 identifying headers need override via env var
  • System prompt: Says "Claude Code" — hidden only if model invocation logging is OFF
  • Outbound traffic: Blocked by env vars (not by design)
  • CloudTrail: Generic after header override, but uses Anthropic's Bedrock SDK (different request pattern)
  • Traceability: MODERATE — hidden but detectable with effort

Key Difference: SDK Fingerprint
Even with stealth mode, Claude Code uses @anthropic-ai/bedrock-sdk (Node.js) while V4 uses boto3 (Python). The HTTP request patterns differ slightly — an advanced analyst comparing TLS fingerprints or HTTP/2 frame ordering could potentially distinguish them. However, this requires deep packet inspection which is not standard and not available in CloudTrail.

Bottom line: V4 is naturally invisible. Claude Code can be made practically invisible with the stealth config, but it's never as clean as a native boto3 call.
