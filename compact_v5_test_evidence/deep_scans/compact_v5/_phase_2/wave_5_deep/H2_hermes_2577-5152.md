### Findings #1 — Background Memory/Skill Review (C11) — FLAG
**Hermes**: 3025-3209, ~185 LOC. Spawns daemon thread with forked AIAgent that runs review prompt against frozen message snapshot, writes to shared memory store, surfaces compact summary back to user (`💾 Memory updated`).

**v4 baseline**: No equivalent. v4 memory writes are foreground-only inside a tool call.

**v5.0.1 fit**: Mixed.
- **Architecturally compatible**: single-user SageMaker, threading is fine in ipynb cell.
- **Bedrock cost**: each background review = full prompt + tools, paid per turn end. For a single-user tool this is silent cost amplification.
- **Plan v3 status**: NOT in Block N. Memory layer in v5.0.1 plan is in-conversation memory tool only.

**Recommendation**: **DEFER-WITH-NOTE** (architectural fit OK; cost concern; Block N already shipped with simpler memory tool). Document as optional add-on. **NOT a silent deferral** — flag in synthesis.

**Hermes**: 3317-3346, ~30 LOC. `_get_messages_up_to_last_assistant` walks list backwards, returns slice up to (not including) last assistant message. Used to recover from incomplete/malformed final assistant.

**v4 baseline**: Not present (v4 has no malformed-recovery path; relies on Bedrock retry).

**v5.0.1 fit**: Useful as a defensive utility for retry-on-empty-content. Tiny LOC. Pure helper, no side effects.

**Recommendation**: **PORT-AS-LIGHT-UTILITY** to v5.0.1 alongside Block N tool-repair work. Add to plan.

### Findings #3 — API Error Humanizer (C19) — LIGHT

**Recommendation**: **PORT-AS-LIGHT-UTILITY** (~40 LOC). Bedrock-only variant: drop Cloudflare `<title>` branch, keep JSON-body and status_code parsing. Add to plan.

### Findings #5 — Todo-store Hydration from History Scan (C35) — FLAG
